# SPN 专线投诉诊断业务流

## 工作台业务边界（2026-08-27 校准）

1. WAIMO 通过 Task-T 将一个投诉诊断任务下发给工作台。工作台使用 SDK 校验并提取
   投诉参数，搜索/加载工作流。
2. 工作流向两个不同地市 OMC 并行下发含地市诊断输入的 Task-T。两路结果都完成后，
   工作台 join 节点仅执行一次汇总分析，把真实汇总结果返回 WAIMO。
3. 工作台到 OMC 通过直连通道下发 Task-T 诊断任务。
4. Authorization-T 和 Notification-T 由工作台在各自业务时机独立触发，不是工作流
   DAG 节点。Task、Authorization、Notification 使用不同的 transport/runtime/context/通道。
5. OMC 对诊断后的抢通方案做白名单精确匹配；命中后自动执行，并通过已建立的
   Notification-T 长连接上报结果。工作台收到抢通结果后关闭对应订阅；ACK 不是抢通结果。


### 表格一：专线业务投诉诊断接口（核心诊断）

| 项目          | 详细说明                                                                                                                                                            |
|:--------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **接口名称**  | 专线业务投诉诊断接口                                                                                                                                                |
| **协议/模式** | A2A-T Task-T                                                                                                                                                        |
| **调用方向**  | 工作台智能体 -> SPN Domain Agent（OMC）                                                                                                                             |
| **功能描述**  | 工作台智能体下发诊断请求，OMC完成网络侧故障根因诊断并返回结果。                                                                                                     |
| **请求参数**  | **必填：**<br>1. 任务对象：业务名称、业务标识或接入端口三者至少一个<br>2. 投诉分类（专线质差 / 专线中断）<br>3. OSS 侧事件流水号<br><br>**可选：**<br>4. 问题发生时间<br>5. 投诉详情 |
| **响应内容**  | Task-T 只返回本地诊断结论：<br>1. 诊断结果<br>2. 故障根因/根因位置与描述<br>3. 修复建议。抢通方案和执行结果不拼入 Task-T 响应，统一走独立 Notification-T 订阅通道。 |

### 表格二：专线业务投诉诊断协商接口（参数修正）

| 项目                       | 详细说明                                                                                                                                                                                                           |
|:---------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **接口名称**               | 专线业务投诉诊断协商接口                                                                                                                                                                                           |
| **协议/模式**              | A2A-T Negotiation-T                                                                                                                                                                                                |
| **调用方向**               | SPN Domain Agent（OMC） <--> 工作台智能体（双向）                                                                                                                                                                  |
| **功能描述**               | 当OMC发现任务参数有误或缺失时，反向发起协商，请求工作台智能体补全或修正信息。                                                                                                                                      |
| **协商请求（OMC→工作台）** | **触发条件：** <br>1. 必选参数缺失（如任务对象、投诉分类或 OSS 侧事件流水号）<br>2. 参数取值错误（如投诉分类不在枚举范围内）<br>3. 参数语义校验错误（如应为逻辑口却下发了物理口）<br><br>**请求内容：** 明确指出缺失/错误的参数及修正建议。 |
| **协商响应（工作台→OMC）** | 工作台智能体理解协商请求，返回强类型 Accept / Reject / Abort。Information Reject 必须对每个无法提供的请求信息项逐项说明原因，不能只返回一个汇总拒绝原因。 |
| **协商完成（OMC）**        | OMC确认协商信息完成后，继续执行诊断任务，并最终返回诊断结果（同表格一响应内容）。                                                                                                                                  |

### 表格三：业务抢通消息订阅与上报接口（结果通知）

| 项目                       | 详细说明                                                                                                                      |
|:---------------------------|:------------------------------------------------------------------------------------------------------------------------------|
| **接口名称**               | 业务抢通消息订阅接口 / 消息上报                                                                                               |
| **协议/模式**              | A2A-T Notification-T                                                                                                          |
| **功能描述**               | 用于工作台订阅抢通结果，以及OMC通过SSE流主动上报抢通结果消息。                                                                |
| **订阅请求（工作台→OMC）** | **包含内容：** <br>1. 消息主题<br>2. 上报消息数据格式（需包括：投诉事件流水号、分段业务标识、抢通方案执行结果、抢通方案详情） |
| **订阅响应（OMC→工作台）** | **成功：** Notification-T metadata 返回“订阅结果：成功”，任务进入 `WORKING`。<br>**失败：** 返回 `FAILED` 及失败原因。 |
| **消息上报（OMC→工作台）** | 基于订阅时指定的数据格式，通过 **SSE** 先推送 `recovery-plan`（未启动），白名单命中并执行后再推送 `recovery-result`（已结束）；结果、取消或宿主关闭才结束通道。 |

### 表格四：专线业务抢通授权接口（自动执行授权）

| 项目                       | 详细说明                                                                                                                          |
|:---------------------------|:----------------------------------------------------------------------------------------------------------------------------------|
| **接口名称**               | 专线业务抢通授权接口                                                                                                              |
| **协议/模式**              | A2A-T Authorization-T                                                                                                             |
| **功能描述**               | 工作台向 OMC 新增、修改、删除或查询抢通授权，OMC 据有效白名单决定是否自动执行抢通。 |
| **授权请求（工作台→OMC）** | **包含内容：** <br>1. 操作类型：新增/修改/删除/查询授权策略<br>2. SDK 模板所定义的策略列表或查询条件 |
| **授权响应（OMC→工作台）** | artifact 的 Authorization-T metadata 返回“授权操作执行结果”；新增/查询成功时还返回策略标识和策略列表，删除必须精确匹配策略标识。失败返回 `FAILED` 且保留原策略。 |
| **后置操作（OMC内部）**    | 授权成功后，当OMC在执行诊断后的业务抢通时，若匹配到已授权项，则**自动执行**业务抢通，并依据**表格三**的订阅通道上报抢通结果消息。 |
